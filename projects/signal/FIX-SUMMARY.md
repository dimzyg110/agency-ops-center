## P0 Fixes (Must Fix)

**After:** Each template type now calls OpenAI GPT-4o with detailed prompts that include:

- GLASS market data (specific prices, product names, competitor names)
- Keyword brief from research step (primary/secondary keywords, search intent)
- Required H2 sections tailored to content type
- Compliance guidelines (935 CMR 500)
- Brand voice from config

**Files changed:**
- `src/pipeline/generate.ts` — Complete rewrite. Added `generateLocationContent()`, `generateProductContent()`, `generateMarketReportContent()`, `generateBlogContent()`, `generateFAQs()`. Each function builds a detailed prompt with real GLASS data and sends it to GPT-4o.
- `src/templates/location-page.ts` — Now accepts LLM-generated body, renders pricing tables, featured products, competitor comparisons, FAQ section, breadcrumbs, related links, CTA section.
- `src/templates/product-page.ts` — Now renders product grids with live GLASS data, FAQ section, pricing info, breadcrumbs, related links.
- `src/templates/market-report.ts` — Now renders category breakdown table, competitor landscape table, report metadata, breadcrumbs, related links.
- `src/templates/blog-post.ts` — Now renders author/date metadata, FAQ section, breadcrumbs, related links.

**Word count targets:**
- Location pages: 1,500-2,000 words
- Blog posts: 1,500-2,000 words
- Market reports: 1,500-2,000 words
- Product pages: 800-1,200 words

### 2. ✅ Humanizer Replaced with LLM-Based Rewriting

**Before:** 3-line find-and-replace that changed "Generated by SIGNAL" to "Generated by SIGNAL (humanized pass)".  
**After:** Full LLM-based humanizer using GPT-4o-mini with comprehensive system prompt implementing all 24 patterns from the humanizer skill (`/data/workspace/skills/humanizer/SKILL.md`).

**File changed:** `src/pipeline/humanize.ts`

**The humanizer now:**
- Sends content through GPT-4o-mini with detailed rewriting instructions
- Removes AI vocabulary (Additionally, Moreover, crucial, pivotal, vibrant, tapestry, etc.)
- Breaks Rule of Three patterns
- Removes em dash overuse
- Kills negative parallelisms ("It's not just X, it's Y")
- Strips all "Generated by SIGNAL" watermarks
- Varies sentence structure and length
- Applies brand voice from config
- Preserves all HTML/JSX tags and JSON-LD schema blocks
- Falls back to rule-based humanization if LLM unavailable
- Safety check: if LLM strips JSX structure, falls back to rule-based

### 3. ✅ Quality Gates Expanded to 12 Checks

**Before:** 3 checks (H1, JSON-LD string presence, length > 700 chars).  
**After:** 12 automated quality checks with severity levels (error vs warning).

**File changed:** `src/pipeline/review.ts`

**New checks:**
1. H1 heading presence (error)
2. JSON-LD schema markup (error)
3. Minimum word count by content type (error) — 1200 for location/report, 600 for product, 1000 for blog
4. Cannabis compliance — 935 CMR 500 (error) — 16 prohibited health claim patterns + youth targeting detection
5. Duplicate content detection (warning) — heading repetition detection
6. Readability score — Flesch-Kincaid (warning) — target 30-90
7. Keyword density (warning) — target 0.5-3.0% when keyword provided
8. Schema validation (error) — checks required properties per content type (address for LocalBusiness, offers for Product, Q&A pairs for FAQ)
9. Internal link count (warning) — minimum 3 links
10. Meta description length (warning) — 50-160 characters
11. Heading structure (warning) — minimum 3 H2 headings
12. AI watermark detection (error) — blocks content with "Generated by SIGNAL"

**Pipeline behavior:** Error-severity failures block publishing. Warning-severity issues are logged but don't block.

### 4. ✅ Schema Markup Complete with Required Properties

**Before:** Generic `{ "@context": "https://schema.org", "@type": type, ...payload }` with no required properties.  
**After:** Five dedicated schema generators with full required properties.

**File changed:** `src/seo/schema-markup.ts`

**New schema types:**
- **LocalBusiness/Store**: name, url, description, PostalAddress (street, city, state, zip, country), GeoCoordinates (lat/lng), telephone, openingHours, priceRange, image, areaServed
- **Product**: name, description, Brand object, sku, image, category, Offer (price, priceCurrency, availability), AggregateRating
- **FAQPage**: proper Question/acceptedAnswer pairs from generated FAQ content
- **Article**: headline, description, author (Person), datePublished, dateModified, publisher (Organization with logo), image, url
- **BreadcrumbList**: proper ListItem array with position, name, item URL

All generated as valid JSON-LD that follows Google's Rich Results Test requirements.

### 5. ✅ Research Module with Real Keyword Intelligence

**Before:** Fetched GLASS data from first operator only, returned raw data.  
**After:** Comprehensive research pipeline with keyword intelligence.

**File changed:** `src/pipeline/research.ts`

**New capabilities:**
- **Google Autocomplete**: Fetches suggestions from `suggestqueries.google.com/complete/search` for the primary keyword
- **Multi-operator GLASS fetch**: Fetches prices and products from ALL operators (not just first), with partial failure tolerance
- **LLM Keyword Brief**: Uses GPT-4o-mini to generate a structured KeywordBrief including:
  - Primary keyword (optimized)
  - 3-5 secondary keywords
  - 3-5 long-tail keyword variations
  - Search intent classification (transactional/informational/navigational/local)
  - 6-8 suggested H2 sections for the content
  - 5-7 FAQ questions users would ask
  - Target word count
- **Fallback brief**: When no API key available, generates sensible defaults based on content type

## P1 Fixes (Important)

### 6. ✅ GLASS Data Injection with Meaningful Narratives

**Before:** 3 generic summary strings ("Local average across tracked competitors is about $38.50").  
**After:** Rich data structures with narrative generation.

**File changed:** `src/glass/data-injector.ts`

**New data injection:**
- **CategoryPriceBreakdown**: avg/min/max price and product count per category
- **FeaturedProducts**: 8 top products selected across categories (cheapest per category, then fill)
- **CompetitorComparisons**: up to 5 operators with avg price, product count, strongest category
- **MarketStats**: totals for operators, products, in-stock, out-of-stock, categories, prices
- **MarketNarratives**: 4 narrative paragraphs:
  - `pricingNarrative`: "Flower averages $38.50 across East Boston-area dispensaries, with prices ranging from $25 to $55"
  - `inventoryNarrative`: "Across 5 tracked dispensaries in East Boston, there are 145 products currently in stock out of 200..."
  - `competitiveNarrative`: "The East Boston cannabis market includes 5 active dispensaries. Competition keeps pricing competitive..."
  - `valueProposition`: Market positioning context based on actual price data

### 7. ✅ Internal Linking with Topical Authority Architecture

**Before:** `suggestInternalLinks()` took first 5 URLs with identical "Related: keyword" anchor text. Never called by any template.  
**After:** Hub-and-spoke topic cluster architecture.

**File changed:** `src/seo/internal-links.ts`

**New capabilities:**
- **`buildTopicCluster()`**: Generates hub-and-spoke links:
  - Location pages → sibling town pages + relevant product pages
  - Product pages → location pages + sibling product pages
  - Blog/report pages → top location and product pages
- **`buildBreadcrumbs()`**: Generates breadcrumb trail: Home → Section → Current Page
- **Context-aware links**: Each link has a context (breadcrumb, inline, related, hub) for template rendering
- **All templates** now render breadcrumb navigation, related content section, and inline cross-links
- **URL generation** follows consistent patterns: `/locations/east-boston`, `/products/flower`, `/blog/slug`

### 8. ✅ SEO-Optimized Meta Generation

**Before:** Simple `keyword | location` concatenation with basic description.  
**After:** Full SEO-optimized meta tag generation.

**File changed:** `src/seo/meta.ts`

**New meta output:**
- **Title tags**: `keyword | location | brand` — intelligently truncated to under 60 chars (tries full format, then shorter variations)
- **Meta descriptions**: CTA prefix (Find/Shop/Read) + keyword + differentiator — under 160 chars
- **Open Graph tags**: ogTitle, ogDescription, ogType (article/product/business.business per content type)
- **Canonical URLs**: Full URL with proper type-based path
- **Dual API**: Supports both old `generateMeta(keyword, location)` and new object `generateMeta({ keyword, location, clientName, contentType, domain, slug })`

### 9. ✅ Batch Pipeline Operations

**Before:** One PR per content file. No batch generation.  
**After:** `signal pipeline --client ch --type all` generates all content types with batch PR.

**Files changed:** `src/index.ts`, `src/pipeline/publish.ts`, `src/publishers/github-pr.ts`

**New capabilities:**
- **`--type all`**: Generates location pages for all configured towns, product pages for all categories, and a market report — all in one command
- **Partial failure tolerance**: Failed generations are logged but don't stop the pipeline. Only successful files are published.
- **Batch PR**: `runBatchPublish()` creates a single PR with multiple files using Git tree API (create blobs → create tree → create commit → create branch → create PR)
- **Rich PR descriptions**: PR body includes file list, quality check summary, and review notes
- **Progress logging**: Each generation step is logged with content type and target

### 10. ✅ Retry/Error Handling for LLM and GitHub API Calls

**Before:** No retry logic anywhere. Single failures killed the pipeline.  
**After:** Exponential backoff retry on all external API calls.

**Files changed:** `src/llm/openai-client.ts` (new), `src/publishers/github-pr.ts`

**LLM retry (OpenAI):**
- 3 retries with exponential backoff (1s, 2s, 4s + jitter)
- Retries on: 429 (rate limit), 500/502/503 (server errors), timeouts, ECONNRESET
- Model selection by role: `gpt-4o` for content, `gpt-4o-mini` for humanizer/research
- Centralized client with `callLLM()`, `generateContent()`, `humanizeContent()`, `researchQuery()` helpers

**GitHub retry:**
- 3 retries with exponential backoff on all API calls
- Retries on: 403 (rate limit), 429, 500/502/503
- `withRetry()` wrapper used for every Octokit call
- Branch name collision avoidance: if branch exists, appends random suffix
