### Pi/Antigravity Tool Bug - FIXED (22:16 UTC)

**Root Cause Identified:**
- Bug was NOT model-specific (affected all Antigravity models using tools)
- Pi's `google-shared.ts` was missing `thoughtSignature` field on `functionResponse` parts
- When Claude thinking models use tools, Google's API requires `thoughtSignature: "interleaved-thinking-2025-05-14"` on BOTH `functionCall` AND `functionResponse`
- Pi was only adding it to `functionCall`, not `functionResponse`
- This caused "Request contains an invalid argument" error on second API call (after tool results sent back)

**Diagnosis Process:**
- Spawned test subagent with tool use, checked transcript
- Error happened AFTER tool results returned (first call worked, second failed)
- Examined Pi source at `/tmp/pi-mono/packages/ai/src/providers/google-shared.ts`
- Found `functionCall` had thoughtSignature logic, `functionResponse` didn't
- Confirmed pattern: `requiresToolCallId()` returns true for Claude models

**Fix Applied:**
- File: `/tmp/pi-mono/packages/ai/src/providers/google-shared.ts` (lines 197-207)
- Added thoughtSignature detection for Claude thinking models
- Added conditional `thoughtSignature` field to `functionResponsePart` object
- Rebuilt Pi: `cd /tmp/pi-mono && npm run build`
- Compiled successfully at 22:16 UTC

**Code Change:**
```typescript
const isClaudeThinking = model.id.toLowerCase().includes("claude") && model.id.toLowerCase().includes("thinking");
const requiresThoughtSig = isClaudeThinking || model.id.includes("gemini-3");

const functionResponsePart: Part = {
    functionResponse: { ... },
    ...(requiresThoughtSig && { thoughtSignature: "interleaved-thinking-2025-05-14" }),
};
```

### Key Lessons Learned
1. **Never say "deployed" without E2E testing** - Randy was right to push back
2. **Database conflicts:** When existing tables exist, just drop them - don't overthink schema isolation
3. **Clerk routing:** path-based routing causes redirect loops with React Router - use hash routing
4. **Railway has network restrictions** from sandbox - use Railway CLI or Railway service context for DB access
5. **Wrong `codex` binary:** `/usr/local/bin/codex` is a blog tool, not OpenAI Codex CLI
6. **Multiple Railway projects:** Always verify which project is linked before claiming deployment success
7. **Testing is mandatory:** Spawn Playwright agents to verify actual user flows, don't assume it works
